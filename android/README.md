# Famical Android APK v1.0.0

삼성 갤럭시에 설치해 기존 NAS 가족 달력을 사용하는 안드로이드 앱입니다. 네이티브 Android WebView 컨테이너로 NAS의 기존 웹 화면을 표시합니다. NAS 서버/API를 새로 만들지 않고 현재의 로그인·교대조·음력·기간 일정·개인/공유 일정을 그대로 사용합니다.

## 설치

1. 저장소의 [다운로드 폴더](../downloads/)에서 `famical-android-1.0.0-debug.apk`를 받습니다. GitHub 파일 화면에서는 Raw/Download raw file을 선택합니다.
2. 삼성 기기에서 내려받은 APK를 열고 설치합니다. Android에서 요청하면 해당 브라우저 또는 내 파일 앱의 ‘이 출처 허용’으로 설치를 승인합니다. 회사 관리 기기나 삼성 보안 설정에 따라 직접 설치가 제한될 수 있습니다.
3. ‘우리 가족 달력’을 실행합니다.
4. 기존 달력이 열리는 **HTTPS 도메인**을 입력하고 연결하기를 누릅니다. 예: `https://calendar.example.com` (실제 주소로 바꾸세요).
5. NAS에 만들어 둔 가족 계정으로 로그인합니다. APK에 기본 계정이나 비밀번호는 없습니다.

주소는 도메인과 선택 포트까지만 입력합니다. `/api`, 경로, 사용자 이름, 비밀번호, 쿼리 문자열은 넣지 않습니다. 기본 HTTPS 포트는 443입니다. 별도 HTTPS 포트는 `https://calendar.example.com:8443`처럼 입력할 수 있습니다.

## 사용

- 상단 **새로고침**: NAS 달력의 처음 화면을 다시 엽니다.
- 상단 **서버**: NAS 도메인을 변경합니다. 다른 서버로 변경하면 앱의 기존 쿠키와 웹 저장소를 지우고 다시 로그인합니다.
- 뒤로 가기: 웹 화면 이력이 있으면 뒤로 이동하고, 없으면 앱을 종료합니다.
- 로그인 세션은 NAS의 쿠키 정책에 따라 유지됩니다. 앱은 로그인 비밀번호를 별도로 저장하지 않습니다.
- 인터넷과 NAS 서버가 필요합니다. 오프라인 일정 편집, 푸시 알림, Android 기본 캘린더 동기화는 포함하지 않습니다.
- APK는 Android용입니다. iPhone은 기존 Safari 홈 화면 웹앱을 사용합니다.

NAS 웹앱의 `v1.2.0`과 Android 앱의 `v1.0.0`은 별도 버전입니다. APK 설치만으로 NAS 서버 버전이 업데이트되지는 않습니다.

## 연결 조건

- NAS의 역방향 프록시·인증서는 [setupmanual.md](../setupmanual.md) 절차대로 설정합니다.
- 유효한 HTTPS 인증서가 필요합니다. HTTP나 인증서 오류를 무시하는 접속은 지원하지 않습니다.
- 외부에서 이미 접속되는 캘린더 주소를 사용합니다. DSM 관리 화면 주소나 NAS의 `127.0.0.1:8090`을 앱에 넣지 않습니다.
- 서버 응답 오류가 나오면 같은 도메인을 휴대전화 Chrome에서 열어 NAS 접속부터 확인합니다.

## 테스트 배포와 업데이트

현재 APK는 직접 설치해 기능을 확인하는 **debug 서명 테스트 빌드**입니다. Google Play 배포용 릴리스 빌드는 아닙니다. Android 실기기 설치·터치·키보드·폴더블 전환 동작은 기기에서 최종 확인해야 합니다.

동일 앱을 덮어 설치하려면 기존과 같은 서명 키가 필요합니다. 이 저장소에는 서명 키나 비밀번호를 올리지 않습니다. 장기 배포 전에는 소유자가 보관하는 별도 릴리스 키를 사용해야 합니다. 키가 다른 APK는 기존 앱을 제거해야 설치될 수 있습니다. 이 경우 앱의 서버 주소·로그인 정보는 초기화되지만 NAS에 저장된 일정은 삭제되지 않습니다.

## 개발 환경에서 빌드

Android Studio에서 이 `android` 폴더를 열면 됩니다. JDK 17 이상(권장 JDK 21), Android SDK 35, Build Tools 35가 필요합니다. Android Gradle Plugin 8.9.2와 Gradle 8.11.1을 사용합니다.

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Windows에서는 `gradlew.bat`를 사용합니다. 결과 파일은 `app/build/outputs/apk/debug/app-debug.apk`입니다. Android Studio의 SDK 설정 또는 `ANDROID_HOME`이 올바르게 지정되어야 합니다. `local.properties`, 빌드 캐시, 서명 키는 GitHub에 올리지 않습니다.

주소 유효성·동일 출처 제한을 단위 테스트합니다. 브라우저 JavaScript 브리지는 사용하지 않습니다. WebView는 파일 접근·혼합 HTTP 콘텐츠·서드 파티 쿠키를 차단하고, 다른 도메인으로의 사용자 링크는 외부 브라우저에서 엽니다.
